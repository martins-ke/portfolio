AgroSync: Enterprise Cloud Agricultural Management Platform

A complete architectural breakdown of a production cloud farm management system built for commercial operations — featuring hierarchical PBAC, operational financial shielding, and 3NF relational modeling.

Executive Summary

Business Problem & System Scope

Commercial agricultural enterprises operate under hierarchical delegations: Farm Owners/Admins oversee executive finances, Farm Managers manage allocated project categories, and Field Supervisors coordinate day-to-day laborers and harvests on the ground.

Core Challenges Addressed:

  • The Financial Privacy Dilemma: Field supervisors need to record operational transactions (harvest kilograms, seeds used, labor shifts) without seeing sensitive business revenue, product margins, or enterprise balance sheets.
  • Distributed Payment Reconciliation: Customers and suppliers settle accounts via recurring, partial installments. The system needed a strict FIFO debt allocation algorithm to avoid ledger drift.
  • Distributed Concurrency & ID Collisions: Preventing primary key collisions across concurrent project creation and transaction deletions without relying on brittle client IDs.
System Design

The platform is structured as a decoupled micro-monolith: a reactive single-page client coupled with a stateless Spring Boot API and managed relational database.

Database Modeling

Relational Entity-Relationship Diagram (3NF)

The database schema was normalized to Third Normal Form (3NF) to guarantee consistency across multi-user environments while enforcing strict referential integrity.

AGROSYNC_CORE_SCHEMA.SQL SQL / DDL 
-- User Privilege and Role Partitioning
CREATE TABLE users (
    id VARCHAR(36) PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    role ENUM('ADMIN', 'MANAGER', 'SUPERVISOR') NOT NULL,
    privileges JSON,
    max_project_capacity INT DEFAULT 5
);

-- Category & Project Scope Mapping
CREATE TABLE projects (
    id VARCHAR(36) PRIMARY KEY,
    category_id VARCHAR(36) REFERENCES categories(id),
    manager_id VARCHAR(36) REFERENCES users(id),
    supervisor_id VARCHAR(36) REFERENCES users(id),
    status ENUM('ACTIVE', 'COMPLETED') NOT NULL
);

-- Commercial Sales with Stored Computed Balance & FIFO tracking
CREATE TABLE sales (
    id VARCHAR(36) PRIMARY KEY,
    project_id VARCHAR(36) REFERENCES projects(id),
    customer_id VARCHAR(36) REFERENCES customers(id),
    total_amount DECIMAL(12,2) NOT NULL,
    amount_paid DECIMAL(12,2) DEFAULT 0.00,
    balance DECIMAL(12,2) GENERATED ALWAYS AS (total_amount - amount_paid) STORED
);
Transaction Isolation & Concurrency: All financial operations and inventory deductions run under `@Transactional(isolation = Isolation.READ_COMMITTED)` with optimistic locking (`@Version`) to guard against stale updates.
Access Control

Hierarchical PBAC & The Financial Privacy Shield

Unlike traditional role systems where permissions are static, AgroSync enforces Privilege-Based Access Control (PBAC) combined with project delegation:

1. Multi-Tier Delegation Hierarchy: Farm Admins delegate categories to Managers; Managers assign projects to Field Supervisors. Supervisors only possess visibility into records within their active assigned projects.
2. Financial Privacy Shield: Supervisors log harvest amounts, inventory consumption, and farm worker shifts, but all DTO projections and SQL queries systematically redact financial amounts, unit sale prices, and profit margins.
3. Dynamic Scoped Zero-State UI: When a user has no active assignments, the UI intelligently guides them with contextual setup cards rather than blank error screens.
